📘 What ComfyUI-Guides Is

ComfyUI is a free tool for creating images and videos with artificial intelligence. It is powerful, but the screen is covered in boxes, wires and menus, and most instructions online assume you already know what all of it means. ComfyUI-Guides fixes that.

This repository is a collection of written guides. Each one takes a single model or a single part of ComfyUI and explains it in ordinary language: what the box does, why it is there, which file it needs, and what happens when you change the number inside it. There is no programming involved and nothing to compile. You read the guide, you follow along, and the screen starts to make sense.

The guides are written for people who have never touched a node editor before. Every term is explained the first time it appears, and every step is written in the order you actually do it. If you have ever downloaded an AI model, opened ComfyUI, and immediately closed it again because it looked like a wiring diagram, these guides are made for you.

💻 Windows Requirements at a Glance

ComfyUI works on a normal Windows computer, but the models in these guides are large. The following is a comfortable starting point for the workflows described here.

  • Operating system: Windows 10 or Windows 11, 64-bit.
  • Memory: 16 GB of system memory or more.
  • Graphics card: An NVIDIA graphics card with at least 8 GB of video memory is the smoothest option. 12 GB or more gives you room for the larger model files.
  • Storage: At least 30 GB of free space on your main drive, plus more if you plan to keep several models at once.
  • Drivers: The current graphics card driver from your card manufacturer.

If your computer has less than this, the guides still explain what each setting does — you will simply need to use the smaller versions of the model files, which are described inside each guide.

📁 File Names, Explained

One of the most common points of confusion is the file extension at the end of a downloaded model. The guide explains each one, but here is the short version.

  • .safetensors — The standard format for models today. It loads quickly and is the format most guides assume you are using.
  • .ckpt — An older format. It still works, but only download these from sources you trust.
  • .gguf — A compressed format used when memory is tight. It runs a little slower but takes up less space.
  • .pth — Usually a helper file rather than a full model, such as an upscaler or an embedding.
  • .json — A workflow file. This is not a model at all; it is a saved layout of boxes and wires that you drag onto the ComfyUI window to rebuild the whole setup at once.

🗂️ Where Each File Belongs

ComfyUI only finds a model if it sits in the right folder. Placing a file in the wrong place is the single most common reason a box shows up in red. The guides list the exact path for every file, and the pattern looks like this:

  • ComfyUI/models/checkpoints — Full image models.
  • ComfyUI/models/diffusion_models — The model component used by the newer video and image workflows.
  • ComfyUI/models/loras — Small add-on files that change style or subject.
  • ComfyUI/models/vae — The file that turns the model's numbers into a finished picture.
  • ComfyUI/models/clip — The file that reads your written prompt.
  • ComfyUI/models/upscale_models — Files that enlarge a finished image.

🎛️ Settings That Actually Matter

A ComfyUI workflow contains dozens of numbers. In practice, only a handful change what you see. The guides explain each of these in plain words, with an example of what happens if you raise or lower it.

  • Steps — How many passes the model makes. More steps means more detail and more waiting. There is a point where extra steps stop helping.
  • CFG or guidance scale — How strictly the model follows your words. Too low and it ignores you; too high and the image becomes harsh and over-saturated.
  • Sampler — The method used to draw the image. Different samplers produce slightly different results, and the guide names the ones worth trying first.
  • Seed — The random number that decides the starting point. Keep the same seed to reproduce an image; change it to get a new one.
  • Denoise — How much of the starting image the model is allowed to replace. Only used when you supply an existing image.
  • Width and height — The output size in pixels. Sizes that are not multiples of 64 often produce odd results.

✅ Your First Successful Run

The fastest way to learn is to get one finished image on screen. Follow these steps in order and do not change anything else until the image appears.

  1. Make sure ComfyUI is open in your browser and the empty grey canvas is visible.
  2. Open the folder you downloaded and locate the workflow file ending in .json.
  3. Drag that file onto the ComfyUI canvas and let go. The boxes and wires appear on their own.
  4. Find the text box in the middle of the canvas. This is your prompt. Type a short, simple description of the picture you want.
  5. Look for any box outlined in red. A red outline means a file is missing. The guide for your model lists what that box expects and where the file belongs.
  6. Press the Queue Prompt button on the right side of the screen.
  7. Wait. The first run is always the slowest because the model has to be loaded into memory. Later runs are much faster.

When the image appears, you have done it correctly. From that point on, the guides become a reference: change one setting at a time, run it again, and watch what happens.

🛠️ When Something Goes Wrong

ComfyUI reports problems in the window at the bottom of the screen and in the black console window that opened alongside it. Most errors are not serious. Here are the ones you are most likely to meet, and what they mean.

  • A box is red and will not connect. A required file is missing or is in the wrong folder. Check the file name against the guide and move the file to the folder listed there.
  • The run finishes instantly with no image. The prompt box is empty, or the prompt contains only characters the model cannot read. Type a normal sentence.
  • The program stops with a message about memory. The model is larger than your graphics card can hold. Close other programs, reduce the image size, or switch to a smaller version of the model file.
  • The picture looks blurry or broken. The step count is too low or the guidance value is outside the range the guide recommends. Return both to the suggested numbers and try again.
  • Everything worked yesterday and fails today. A file was moved or renamed. Put it back where it was, and avoid renaming files after ComfyUI has seen them.

🔍 Reading the Guides in Order

The guides are numbered so that each one builds on the last. If you are completely new, read them in sequence rather than jumping to a specific model. The first few guides establish the vocabulary — what a node is, what a connection carries, what a loader does — and everything after that uses those words without re-explaining them.

If you already know ComfyUI and only want one model, go straight to that model's guide. Each one stands alone where it matters: it lists its own files, its own folder locations and its own recommended settings. Nothing in a single guide depends on you having read a different one first.

🤝 Sharing and Asking Questions

If a guide helped you, the most useful thing you can do is tell someone else which part was unclear and how you worked it out. That is how the next version gets better. If something is wrong — a file name has changed, a setting is now labelled differently, a step no longer matches the screen — open an issue on the repository and describe what you see. A screenshot of the error is worth more than a paragraph of description.

When asking for help, include the guide you were following, the exact text of the error, and what you had already tried. With those three things, most problems can be answered in a single reply.
